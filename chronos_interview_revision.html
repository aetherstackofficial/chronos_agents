1. Project Overview & Architecture

What it is: A simulated stock market ecosystem where AI agents and algorithmic bots trade against each other in real-time.
Problem Solved: Traditional backtesting uses static historical data. Chronos creates a living, reactive market where massive trades actually move the price and trigger other bots.

Architecture (Distributed Microservices)

  • The Server Node (The Engine) [YOUR CONTRIBUTION]: Runs true_engine.py. The central Limit Order Book listening on TCP Port 5555 via ZeroMQ.
  • The Client Node (The Swarm): 100 PyTorch agents requesting data and sending orders.
  • The Oracle Node (The LLM) [YOUR CONTRIBUTION]: Runs oracle.py. Connects to Google Gemini API to inject macro shocks.
  • The UI Bridge Node [YOUR CONTRIBUTION]: Runs bridge.py and dashboard.html. Uses Flask and Socket.IO to stream data to the frontend.

2. Deep Dive: Key Technical Questions

Q1: How does the Macro Oracle handle Good vs. Bad News?

Answer: The Oracle sends the headline, stock name, and price to Google Gemini. Gemini scores it between -1.0 (Catastrophe) and 1.0 (Euphoria). If the score is positive (e.g., +0.8 for good news), the Oracle sets the action to "BUY" and calculates a massive block of shares to purchase. It dumps this into the engine, driving the price up (Green Profit). If negative, it dumps shares, driving the price down.

Q2: Who are the 100 Agents?

Answer: 15 Market Makers (High-frequency, profit on spread), 4 Institutional Whales (Smart money, trade in huge blocks), and 80 Retail Traders (Rule-based, chaotic, trade on RSI indicators. Liquidated and respawned if bankrupt).

Q3: ZeroMQ vs HTTP: What is Brokerless TCP?

Answer: HTTP has heavy headers and is slow (Request-Response only). ZeroMQ uses raw TCP sockets for pure, high-speed binary messaging. "Brokerless" means there is no middleman server (like Kafka/RabbitMQ); scripts talk Peer-to-Peer, allowing the engine to handle 1,200+ passes/sec.

Q4: How does the Limit Order Book work in the Engine?

Answer: The True Engine uses standard Python Dictionaries (self.bids and self.asks). Bids are buyers, Asks are sellers. Key is the price, value is a list of orders. The payload sends Timestamp, Price, VWAP, RSI, and the top 5 levels of the book to the agents.

Q5: What are WebSockets and Socket.IO doing?

Answer: WebSockets keep a permanent, two-way TCP connection open. Instead of the browser asking for data every second (HTTP Polling), a background thread in Flask asks the Engine for data via ZeroMQ, and pushes it instantly to the browser via socketio.emit().

Q6: What happens if an Agent's Limit Order doesn't match instantly?

Answer: It sits in the dictionary (Order Book). However, a pruning mechanism runs every second (apply_market_regime_physics). If the current price drifts $0.50 away from the order, the order is deleted from the book to prevent RAM bloat and keep the engine fast.

3. Tech Stack Deep Dive

  • Python (Core Logic): Used for rapid development and ML compatibility. Bypassed the GIL limitation by using a microservices pattern (multiple processes) instead of native threads. Used asyncio for non-blocking agent requests.
  • ZeroMQ (Networking): Chosen over REST APIs for ultra-low latency, brokerless Peer-to-Peer communication using raw TCP sockets.
  • Flask & Socket.IO (Bridge): Chosen over Django because a micro-framework was perfect for a single-page app serving real-time WebSocket data.
  • HTML/JS & Lightweight Charts: React's Virtual DOM or standard SVG charts (Chart.js) lag under high-frequency data. Lightweight Charts uses HTML5 <canvas> rendering via GPU for 60fps performance.
  • Google Gemini API: Chosen over traditional NLP (VADER) because LLMs understand complex financial irony and context, rather than just simple keyword counting.

4. Complete Execution Workflow

  1. Initialization: Engine, Swarm, Oracle, and UI run in separate terminals.
  2. User Request: User clicks "Start". Browser sends WebSocket event to Flask. Flask sends ZeroMQ command to Engine to reset.
  3. Market Loop: Agents request LOB state via ZeroMQ. They process data and send BUY/SELL orders.
  4. Execution: Engine matches orders natively in Python dictionaries, updates balances, and calculates new VWAP/RSI.
  5. Data Broadcasting: Flask background thread pulls state from Engine every second and emits it to the Browser via WebSocket.
  6. Macro Shock: User injects news -> Oracle asks Gemini for score -> Oracle sends massive dump order to Engine -> Engine clears book and gaps the price.
